# Фаззинг процессора и компилятора

Это старая лаба из бакалавриата, состоящая из:

- компилятора из S-expr-based языка в выдуманную RISC-машину;
- эмулятора той RISC-машины.

см. [README.md.orig](README.md.orig) для подробностей.

Оба компонента написаны на C++. Используем фаззер [AFL++](https://github.com/AFLplusplus/AFLplusplus).
В качестве изначального корпуса возьмём изначальные тесты (для компилятора -- несколько простых программ на языке, для процессора - результат компиляции этих же программ).

```sh
# собираем с инструментированием
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=afl-c++
cmake --build build

# фаззим компилятор
afl-fuzz -Mmain -i fuzz-inputs/ -o fuzz-outputs -- build/compiler @@ /dev/null
# фаззим процессор
afl-fuzz -Mmain -i procfuzz-inputs/ -o procfuzz-outputs -- build/processor @@
```

В результате после фаззинга обнаружены следующие баги, приводящие к крашу компилятора:

- Парсер не обрабатывал непечатные символы (выше 127 и управляющие ASCII)
- Middle-end очень медленно обрабатывал очень большие запросы на статическую аллокацию (она реализована обычным `std::vector`)

После исправления этих двух багов фаззинг за полчаса больше ничего не нашёл.

В процессоре фаззер также не нашёл крашей за то же ограниченное время, не считая `assert` который должен был быть обычной проверкой валидности входных данных. Это не слишком удивительно, т.к. процессор значительно проще компилятора.
